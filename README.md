# Личный бюджет

Локальный сервис для одного пользователя: доходы и расходы по месяцам с категориями,
сверка плана с фактом, кредиты и ипотека с досрочным погашением, вклады с процентами
и пополнениями, прогноз остатка на счетах и кассовые разрывы.

## Запуск

```bash
git clone https://github.com/s-verbin/budget.git
cd budget
python3 server.py          # http://127.0.0.1:8765
python3 server.py 9000     # другой порт, если 8765 занят
```

Нужен только Python 3.9+ (внешних зависимостей нет), ставить ничего не нужно. Вход
и регистрация не предусмотрены — сервис одного пользователя для себя. Сервер слушает
только `127.0.0.1` — снаружи компьютера недоступен. Пока команда выполняется, сервис
работает; закрытие терминала или `Ctrl+C` его останавливает.

Чтобы запустить в фоне и продолжить работать в том же терминале:

```bash
nohup python3 server.py > server.log 2>&1 &
```

## Остановка

Если сервер запущен на переднем плане (виден в терминале) — `Ctrl+C` в этом окне.

Если запущен в фоне (например, через `nohup &`, как выше, или из другой сессии):

```bash
lsof -nP -iTCP:8765 -sTCP:LISTEN      # найти PID процесса на порту 8765
kill <PID>                            # остановить именно его
```

Одной командой — найти и остановить, если порт 8765:

```bash
kill $(lsof -tiTCP:8765 -sTCP:LISTEN)
```

Остановка сервера не трогает данные — они лежат в файле `budget.db`, не в памяти процесса.

## Данные

Данные лежат в `budget.db` (SQLite) рядом с `server.py`: для резервной копии достаточно
скопировать этот файл (сервер в этот момент можно не останавливать — SQLite это переживёт).
Другой путь к базе: `BUDGET_DB=/путь/к/файлу.db python3 server.py`.

При первом запуске база пустая: на странице есть кнопка «Загрузить пример».

## Что внутри

- **Доходы и расходы** — с повтором (разово, ежемесячно, раз в квартал/полгода/год) и
  необязательной категорией у расходов (для графика «Структура расходов»).
- **Факт** — по каждой статье расхода можно указать, сколько потрачено на самом деле
  в конкретном месяце; эта сумма используется в прогнозе вместо плановой, и приложение
  показывает расхождение факта с планом.
- **Кредиты и ипотека** — аннуитетный платёж, досрочные погашения («сократить срок» или
  «уменьшить платёж»), график остатка долга, разбивка по годам.
- **Вклады** — отдельный счёт со своей ставкой и налогом на проценты, пополнения
  (разовые и регулярные), график роста остатка.
- **Прогноз по месяцам** — остаток на счетах, кассовые разрывы, долговая нагрузка,
  структура трат по категориям (по месяцам и по годам).

Все разделы (Кредиты, Вклады, Доходы, Расходы) сворачиваются; состояние запоминается
в браузере.

## Устройство

- `server.py` — раздаёт `static/` и JSON API: `/api/state` (весь снимок данных),
  `/api/items`, `/api/loans`, `/api/prepayments`, `/api/deposits`,
  `/api/deposit_contributions`, `/api/actuals`, `/api/settings`, `/api/demo`.
- `static/calc.js` — все расчёты (аннуитет, график кредита и вклада, прогноз по месяцам,
  сверка план/факт). Без DOM, тестируется отдельно от интерфейса.
- `static/app.js`, `static/index.html`, `static/style.css` — интерфейс.

## Публичное демо

На [money.sverbin.ru](https://money.sverbin.ru) этот же сервис крутится как песочница —
без входа и **вообще без записи на диск**. У каждого посетителя своя анонимная
cookie-сессия и своя база только в оперативной памяти процесса: никто другой её
не видит, она не попадает в файл и исчезает, как только вы ушли со страницы надолго
(простой дольше пары часов) или сервис перезапустился. Для реальных данных нужен
свой запуск — он всегда пишет в обычный файл на диске, как описано выше.

Демо-режим включается двумя переменными окружения (локально не нужны, в коде по
умолчанию выключены):

```bash
BUDGET_DEMO=1 BUDGET_REPO_URL=https://github.com/s-verbin/budget python3 server.py
```

- `BUDGET_DEMO=1` — включает cookie-сессии с базой в памяти (см. `server.py`,
  `connect()`/`_touch_session()`) и баннер «это песочница».
- `BUDGET_REPO_URL=...` — добавляет ссылку на репозиторий внизу страницы.
